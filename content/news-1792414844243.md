The pull request is blocked. Not by a colleague with a question, but by an automated gatekeeper demanding tribute. The price: one more unit test to nudge the code coverage score from 84.7% to the sanctified 85%. So the developer writes it. They mock the database, mock the network call, mock the configuration service. They assert that a function called `isReady()` does, in fact, return `true`. The pipeline turns green. A merge is permitted. Nothing has been made safer.

This ritual is now more common than the honest, exploratory testing it replaced. The unit test was conceived as a tool for the builder—a carpenter’s jig for ensuring a clean cut every time. It gave developers confidence to refactor tangled code, knowing their small, focused tests would scream if a core assumption was broken. It was a safety net woven from logic.

That was the promise. The reality is now one of compliance. The test suite has become a document submitted for the approval of a faceless bureaucracy. Its primary user is not the developer, but the dashboard. When code coverage became a managerial KPI, the test’s function flipped from a diagnostic tool to a liability shield. The goal is no longer to prevent failure, but to prove you did your part.

The cost of this charade is paid in production. It’s paid during the weekend outage when a critical edge case, too inconvenient to mock, brings the entire payment system down. It is paid in the security breach that sailed past a suite of tests that only verified the “happy path,” because the unhappy paths hurt the metrics.

The test suite is now a pre-written statement for the inevitable incident review. "Did you follow the process?" a director will ask. The team lead can point to the dashboard. "We had 98% coverage," they will say. The alibi holds. The failure must have been someone else’s fault, an act of God, an unforeseeable cosmic ray. The process was followed. The tests were green.

We have meticulously engineered a system that absolves us of responsibility. We write code to test code, and then we point to the output of that first set of code as evidence of our diligence. The green checkmark is not a certificate of quality. It is a receipt for a purchased indulgence, a small price to pay to be able to say, when it all comes crashing down, "Don't look at me. I ran the tests."
